# 課題3-B 利用者の独立実行の手順（2026-11-08 版）

Claude Code 以外の手で、3-B（画面を記録の口につなぐ）を確かめるための手順です。対象は作業ツリー `C:\GitHub\ai-team-studio-evolution-006`（ブランチ `feature/operational-studio-006`、先頭 46ca3b0）。かかる時間の目安は 20〜30 分です。

## 0. はじめに（守ること）

- **運用中のスタジオには触れません**。運用は普段の Chrome の `http://localhost:8773/`（中継 8787）です。この手順では、別のポート **8784（画面）** と **8797（試験用の中継）** だけを使います。運用のタブは開いたままで構いませんが、この手順の操作は 8784 のタブでだけ行ってください。
- 試験用の中継は、`proxy\.env` を読みません（AI の API は呼ばれません）。受け渡しフォルダも運用とは別の一時フォルダです。
- 8784 のページの記録は、ブラウザの中では `127.0.0.1:8784` の住所に入り、運用（`localhost:8773`）の記録とは混ざりません。
- うまくいかない所があっても、その場で直さずに、見えたことを書き留めて次へ進んでください（どの手順で・何が見えたか）。
- PowerShell のウィンドウを **3 つ**使います（A：試験、B：画面のサーバー、C：試験用の中継）。

## 1. Python の試験（PowerShell A）


- 合格：最後に **`Ran 122 tests`** と **`OK (skipped=11)`**。80 秒ほどかかります。
- 途中に出る `[relay] "GET …"` などの行は試験の中の中継の記録で、問題ではありません。

## 2. 画面のサーバーを起動（PowerShell B）


- `Serving HTTP on 127.0.0.1 port 8784` と出れば起動しています。この窓は最後まで閉じません。

## 5. 画面を試験用の中継につなぐ（普段の Chrome）

1. `http://127.0.0.1:8784/index.html` を開く。
   - 最初は中継の URL が運用の既定（8787）になっています。運用の中継には記録の口がないため、上部に「記録を読み込めませんでした」か「中継に届きません」の帯が出て、読むだけの状態になります（運用の中継には何も書きません）。**これで正しい**です。
2. 左下の「AIの接続設定」を開き、「ローカル中継のURL」を **`http://127.0.0.1:8797`** に書き換えて閉じる。
3. ページを読み込み直す（F5）。
4. 合格：左の「この記録：」が **`記録の口・Case 0件（中継 http://127.0.0.1:8797）`**。上部に帯がない。「控え：」が「控え（このブラウザ）に書けます」。

## 6. 画面での操作の確かめ（普段の Chrome、8784 のタブ）

各手順の「合格」が見えたら、次へ進みます。

### 6-1 Case を作る
1. 問いに「独立実行の試験」と書き、AI は **GPT と Meta だけ**にチェックして「始める」。
2. 合格：左の「開いている Case：」が数秒で **`この Case r… ・保存済み`**。観測の欄の GPT に **「送付済み・結果待ち」**（ファイル受け渡し）。上部に帯がない。
   - GPT への依頼は、試験用の受け渡しフォルダ（`%TEMP%\ats-3b-test`）にファイルとして置かれるだけで、GPT には届きません。

### 6-2 手動の AI の返事を貼る
1. 画面の上の Case 番号（`CASE-2026…`）を確かめる。
2. 「結果を受け取る」の欄に、次の文の `<Case 番号>` を実際の番号に置き換えて貼り、「取り込む」。

```
[STUDIO_RESULT]
CASE: <Case 番号>
TASK: <Case 番号>-OBS-Meta
FROM: Meta
SOURCE_ACCESS: なし
CONDITION: 独立実行の試験
OBSERVATION: 独立実行の試験の観測です。十分な長さにするための文を続けます。十分な長さにするための文を続けます。
EVIDENCE: 試験
UNKNOWN: なし
[/STUDIO_RESULT]
```

3. 合格：「Meta の観測として採用」と出て、Meta の欄に観測が入る。「開いている Case：」が `保存済み`。

### 6-3 中継が止まる・戻る
1. PowerShell C で **Ctrl+C** を押し、試験用の中継を止める。
2. 画面の「資料」に `https://example.invalid/while-offline` と入れて「追加」。
3. 合格：数秒で上部に **「中継に届きません。記録は読むだけで…」** の帯が出て、作業欄のボタンが薄くなり押せなくなる。「開いている Case：」が `答え待ち（送り直します）`。
   - 資料の確かめ（その URL を取りに行く処理）が後から終わり、「保存できません（中継に届きません）」という短い赤い表示が出ることがあります。読むだけの間の正しい振る舞いです（15 秒で消えます）。
4. PowerShell C で 4 の起動のコマンドをもう一度打つ（↑キーで出せます）。
5. 合格：**15 秒ほどで**帯が消え、ボタンが元に戻り、「開いている Case：」が `保存済み`。追加した資料が残っている。

### 6-4 2 つのタブで同じ Case を編集する（Claude Code は確かめていない場面）
1. 今のタブ（タブ A）のアドレスをコピーして、新しいタブ（タブ B）で開く。左の一覧から同じ Case を開く。
2. タブ A で資料に `https://example.invalid/from-A` を追加する。合格：A の「開いている Case：」が `保存済み`。
3. **1 分以内に**、タブ B で資料に `https://example.invalid/from-B` を追加する。
4. 合格：タブ B の上部に **「この Case は別の画面で更新されました。読むだけになっています…」** の帯と「最新を読み直す」「自分の編集を JSON で書き出す」が出る。
5. タブ B で「最新を読み直す」。合格：タブ B に `from-A` が見え、`from-B` は見えない（中継の記録は上書きされていない）。帯が「自分の編集が控えに残っています」に変わり、「控えを捨てる」が出る。
6. 「控えを捨てる」→「捨てる」。合格：その帯が消える。
   - 1 分を過ぎると、タブ B が先に A の更新を読み直すため、ぶつからずに B の編集が入ることがあります。それも正しい振る舞いです（その場合は、もう一度 2 からやり直してください）。
   - 注意（3-B の限り）：同じブラウザの 2 つのタブは、控え（保存領域）を共有します。片方のタブが控えを書くと、もう片方の「まだ送っていない編集」の控えを上書きすることがあります。この手順の流れ（A が保存済みになってから B で編集）では、ぶつかる場面の確かめには影響しません。ふだんは 1 つのブラウザで 1 つのタブを使ってください。

### 6-5 読み込みに失敗したときの手動のやり直し（再監査の注意）
1. PowerShell C で Ctrl+C（中継を止める）。タブ A を読み込み直す（F5）。
2. 合格：「中継に届きません」の帯と「読み直す」のボタン（最初の数秒は「中継から記録を読み込んでいます」と出て、それから「中継に届きません」に変わります）。
3. PowerShell C で中継を起動し直し、すぐに帯の **「読み直す」** を押す。
4. 合格：帯が消え、Case の一覧が出る（押さなくても 15 秒ほどで戻ります）。
   - 補足：中継には届くのに設定や Case が読めないとき（中継の記録の異常など）は、自動ではやり直しません。そのときは「読み直す」を押してください。

## 7. 後片付け

1. PowerShell C と B で Ctrl+C（中継と画面のサーバーを止める）。
2. 試験用の記録を消してよければ、PowerShell A で：

```powershell
Remove-Item -Recurse -Force $env:TEMP\ats-3b-test
```

3. 8784 のタブは閉じて構いません（そのブラウザの `127.0.0.1:8784` の控えは残りますが、運用には影響しません）。
