# 制約と未実装（実運用版 001 ＋ 解析ルール v2・段階1b・1c・1d）

推測で「完成」としないための一覧です。2026-10-15 時点。仕様の正本は SPEC.txt（Studio 仕様書）です（第III部が、この一覧の元です）。

## 未検証

- **API コネクタ（openai / anthropic / gemini）は一度も実際に動かしていません。** 開発環境に API キーがなかったためです。モデル名・応答形式・エラー時の挙動はすべて UNKNOWN です。使う前に1件ずつ確かめてください。
- **API 経路の送り直しは、重複処理になる可能性があります。** 中継は依頼ファイルを書いてから API を呼ぶので、API の側で処理が済んだ後に失敗が返ると、Studio は「送付に失敗」と記録します。そこで送り直すと、同じ依頼が2回処理され得ます。API 経路を使う前に、扱いを決めてください。
- mock 経路は、Task ID が「-SYN」で終わるときだけ統合の模擬応答を返します。統合をやり直した「-SYN-2」には、観測の形式を返します。
- 送付に失敗した依頼の送り直しを、実際の AI で人が操作する試験は、まだしていません（試験データでの確認のみ）。
- Claude Code の別セッションによる、ファイル受け渡しの実接続はしていません（Codex Desktop では確認済み）。

## 仕組み上の制約

- **1つのタブで使ってください。** 送付中の印、回収の順番待ち、保存は、タブの間で調整しません。同じ Studio を2つのタブで開くと、同じ依頼が二重に送られたり、保存が上書きされたりする可能性があります。
- **このブラウザに保存できないときは、送付できません。** 依頼文を保存してから送る決まりのためです。保存に失敗したら、まず「記録をJSONで保存」で退避してください。読み込み時に保存が止まった場合は、JSON の読み込みで保存を再開できます。容量不足が原因のときに容量を空ける機能は、まだありません。
- **公開URL（GitHub Pages）だけでは自動化は使えません。** ブラウザから AI へ直接送る手段は手動コピーしかありません。自動の送受信には、手元の PC でローカル中継を起動する必要があります。
- Codex 実行係（段階3-1）は、人か Claude が起動します。中継やスタジオから起動する機能はまだありません（段階3-2で検討）。実行係の状態の表示は、スタジオで開いている Case について、8秒ごとの回収のときに更新されます。失敗の印（`.codex-run`）は人が消します。`--once`・`--watch` は古い未回答の依頼も送ります。Codex の読み取り専用のサンドボックス（利用者 CodexSandboxOffline・グループ CodexSandboxUsers）は、利用者のファイルの多く（`C:\GitHub` 以下、`%LOCALAPPDATA%`、デスクトップ、`%USERPROFILE%\.codex`）を読めます（2026-10-21 の調査で確認）。運用中の `proxy/.env` には、CodexSandboxUsers の読み取り拒否を付けて読めなくしました（`codex exec` の経路でも確認）。`.env` を作り直すと拒否が消えることがあるので、作り直したら `icacls` で確かめてください。ほかの秘密は、サンドボックスから読める場所に置かないでください。返事と実行の照合（SHA-256）は中身が同じかを確かめるだけで、誰が書いたかの証明ではありません。
- agent ルートでは、Claude Code や Codex に「`proxy/exchange/<CASE>/<TASK>/` の to-ファイルを読んで、同じフォルダに from-ファイルを書いて」と伝える必要があります。中継から AI を起動する機能はありません。伝える文面とファイルの完全なパスは、返事を待っている間の「AIへの指示を表示」でコピーできます。パスは中継が実際に書いたファイルの場所です。中継がそれを返さない古い版では Studio が推定し、「推定」と表示します（推定は、まれな文字を含む AI 名では中継の実際の場所と違うことがあります）。
- 「接続を確認」が確かめるのは、中継に届くかどうかだけです。AI との往復ができるかどうかは確かめません。
- 中継からの回収は、今の世代の Task だけを対象にし、書式どおりの返事が採用されるまで続けます。古い世代のファイルは回収しません。
- 「作り直して再送」で作った依頼文は、元の依頼文の代わりになりません。元の依頼文は「依頼文を表示」で出してください。この機能より前に作った Case には、依頼文の本文が保存されていません（実行タスクの本文だけは保存されています）。
- SOURCE の自動確認（ハッシュ計算）は、ブラウザから取得できる URL（CORS 許可あり）に限られます。取得できない場合は中継の `/hash` を使います。どちらも使えなければ「未確認」のままにします。
- 問いに URL があると、ブラウザがその URL を直接取得します（外部への通信）。
- 問いから自動で資料にするのは URL と絶対パスだけです。ファイル名だけの記述は資料になりません（「資料を追加」欄に書けば登録されます）。
- URL は、空白・< > " ' ( )・最初の ASCII 以外の文字（全角の括弧・句読点・日本語など）の手前までを取り出します。括弧を含む URL も途中で切れます。日本語をそのまま含む URL は途中で切れます（ブラウザのアドレス欄からのコピーは、通常は符号化されているので影響しない見込み）。
- 相違点の自動分割（改行が失われた返事）は、既知の層の印が2つ以上ある行だけで行います。層名は語の全体で読みます（SOURCE2 は SOURCE ではありません）。それ以外は原文のまま1項目・未分類で出します。
- ローカルのファイルパスは、ブラウザからは読めません。ファイルを画面にドロップすれば、手元でハッシュを計算します。
- 記録はこのブラウザの localStorage にだけ保存されます。別の PC やブラウザと共有するには、JSON の書き出しと読み込みが必要です。

## 解析の既知の制約（受け入れ済み）

- 識別キー以外の値が全部括弧の短い本物の返事は、見本として扱われます（解析失敗）。
- 項目が2種類以下の短い返事は、ブロックとして扱いません。
- 値の途中にタグの文字列があると、ブロックの切り方が乱れます。入れ子・交差したタグも同様です。
- 1行に詰められた返事の中の重複項目は、検出しません。
- 同じ返事を引用と本物で二重に含むと、どちらか決められず解析失敗になります（再送が必要）。

## 分かっている不具合・改善待ち

- 実行タスクの「やってほしいこと」（NEXT_TASK）は、統合結果の文がそのまま入り、画面では直せません。範囲を限定したいときは、判断の理由に書いてください（理由は実行タスクに載ります）。
- 形式外の返事を、判断（GATE）の前に必ず確認させる仕組み（段階2）は、まだありません。

## 独立性について

- 観測依頼には、ほかの AI の結果を入れていません。ただし、同じ AI を観測・統合・実行に重ねて指名することは止めていません。止めるかどうかは人間が決めることです。
- 統合 AI が観測者と同じだと、自分の観測に寄りやすくなります。画面上で警告はしません（今後の課題）。

## 記録の口（課題3-A、`RECORD_API_3A.md` 0.6.2 §12）

- 画面とはまだつないでいません（3-B）。今のスタジオの記録は、これまでどおりブラウザの保存領域と記録の写しです。
- **フォルダの差し替えの競合**：読み書きの直前にすべての道を確かめますが、確かめてから書くまでの間に、別のプログラムが `_record` の中のフォルダをリンクに差し替えると防げません。このときは記録の保護を保証しません（この PC で利用者の権限で動くプログラムにしかできず、そのプログラムは記録を直接書き換えることもできます）。
- **開いた後の書き換え**：開いたファイルが確かめたファイルと同じであることは確かめますが、開いた後に同じファイルの中身を別のプログラムが書き換えるのは防げません（偶然の破損としては sha256・metaSha256 で見つかります）。
- **手での変更**：中継が動いている間に `_record` のファイルを手で変えると、起動時に作った送り直しの索引と食い違います。手で変えるときは、先に中継を止めてください。
- **電源断**：止まる直前の書き込みが、前の版に戻ることがあります（半分書けた正本は残りません）。試験では確かめられません。
- **意図的な改変**：`sha256`・`metaSha256` は鍵を使わないので、中身とハッシュを一緒に書き換えられると気づけません。この PC の中のプログラムを信頼する前提です。
- 動いている間に見つかった Case の問題（壊れた版・リンク・ハードリンク・正本のない履歴）は、中継を再起動するまで解けません。
- 同じ `proxy/exchange` を使う中継は 1 つだけです。2 つ目は「別の中継が同じ記録を使っています」と出して起動しません。`start_studio.ps1` がこの失敗を見分けて知らせるかは、まだ確かめていません。
- シンボリックリンクを使った試験は、この PC では権限がなく skip になります（ジャンクションとハードリンクは試しています）。
