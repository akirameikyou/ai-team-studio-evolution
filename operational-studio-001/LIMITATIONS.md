## 仕組み上の制約

- **公開URL（GitHub Pages）だけでは自動化は使えません。** ブラウザからAIへ直接送る手段は手動コピーしかありません。自動の送受信には、手元のPCでローカル中継を起動する必要があります。
- agent ルートでは、Claude Code や Codex に「`proxy/exchange/` の to-ファイルを読んで from-ファイルを書いて」と一度伝える必要があります。中継から相手のAIを起動する機能はありません。
- SOURCE の自動確認（ハッシュ計算）は、ブラウザから取得できるURL（CORS 許可あり。例：raw.githubusercontent.com）に限られます。取得できない場合は中継の `/hash` を使います。どちらも使えなければ「未確認」のままにし、確認済みとは表示しません。
- ローカルのファイルパスは、ブラウザからは読めません。そのため「未確認」になります。ファイルを画面にドロップすれば、手元でハッシュを計算します。
- 記録はこのブラウザの localStorage にだけ保存されます。別のPCやブラウザと共有するには、JSON の書き出しと読み込みが必要です。
- 差分の自動検出は「SOURCE への到達状態がAIによって違う」場合だけです。内容の違いを判定し、どの層（ORIGIN）で生じたかを付けるのは、統合AIと人間の役割です。

## 独立性について

- 観測依頼には、ほかのAIの結果を入れていません。ただし、同じAIを観測・統合・実行に重ねて指名することは止めていません。止めるかどうかは人間が決めることです。
- 統合AIが観測者と同じだと、自分の観測に寄りやすくなります。画面上で警告はしません（今後の課題）。
