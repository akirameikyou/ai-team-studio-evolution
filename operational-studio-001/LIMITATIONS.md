# 制約と未実装（実運用版 001 ＋ 解析ルール v2・段階1b・1c）

推測で「完成」としないための一覧です。2026-10-15 時点。仕様の正本は「Studio 仕様書 v0.6」です（第III部が、この一覧の元です）。

## 未検証

- **API コネクタ（openai / anthropic / gemini）は一度も実際に動かしていません。** 開発環境に API キーがなかったためです。モデル名・応答形式・エラー時の挙動はすべて UNKNOWN です。使う前に1件ずつ確かめてください。
- **API 経路の送り直しは、重複処理になる可能性があります。** 中継は依頼ファイルを書いてから API を呼ぶので、API の側で処理が済んだ後に失敗が返ると、Studio は「送付に失敗」と記録します。そこで送り直すと、同じ依頼が2回処理され得ます。API 経路を使う前に、扱いを決めてください。
- mock 経路は、Task ID が「-SYN」で終わるときだけ統合の模擬応答を返します。統合をやり直した「-SYN-2」には、観測の形式を返します。
- 送付に失敗した依頼の送り直しを、実際の AI で人が操作する試験は、まだしていません（試験データでの確認のみ）。
- Claude Code の別セッションによる、ファイル受け渡しの実接続はしていません（Codex Desktop では確認済み）。

## 仕組み上の制約

- **1つのタブで使ってください。** 送付中の印、回収の順番待ち、保存は、タブの間で調整しません。同じ Studio を2つのタブで開くと、同じ依頼が二重に送られたり、保存が上書きされたりする可能性があります。
- **このブラウザに保存できないときは、送付できません。** 依頼文を保存してから送る決まりのためです。保存に失敗したら、まず「記録をJSONで保存」で退避してください。読み込み時に保存が止まった場合は、JSON の読み込みで保存を再開できます。容量不足が原因のときに容量を空ける機能は、まだありません。
- **公開URL（GitHub Pages）だけでは自動化は使えません。** ブラウザから AI へ直接送る手段は手動コピーしかありません。自動の送受信には、手元の PC でローカル中継を起動する必要があります。
- agent ルートでは、Claude Code や Codex に「`proxy/exchange/<CASE>/<TASK>/` の to-ファイルを読んで、同じフォルダに from-ファイルを書いて」と伝える必要があります。中継から AI を起動する機能はありません。指示の文面とファイルの場所は、まだ画面に出ません。
- 「接続を確認」が確かめるのは、中継に届くかどうかだけです。AI との往復ができるかどうかは確かめません。
- 中継からの回収は、今の世代の Task だけを対象にし、書式どおりの返事が採用されるまで続けます。古い世代のファイルは回収しません。
- 「作り直して再送」で作った依頼文は、元の依頼文の代わりになりません。元の依頼文は「依頼文を表示」で出してください。この機能より前に作った Case には、依頼文の本文が保存されていません（実行タスクの本文だけは保存されています）。
- SOURCE の自動確認（ハッシュ計算）は、ブラウザから取得できる URL（CORS 許可あり）に限られます。取得できない場合は中継の `/hash` を使います。どちらも使えなければ「未確認」のままにします。
- 問いに URL があると、ブラウザがその URL を直接取得します（外部への通信）。
- ローカルのファイルパスは、ブラウザからは読めません。ファイルを画面にドロップすれば、手元でハッシュを計算します。
- 記録はこのブラウザの localStorage にだけ保存されます。別の PC やブラウザと共有するには、JSON の書き出しと読み込みが必要です。

## 解析の既知の制約（受け入れ済み）

- 識別キー以外の値が全部括弧の短い本物の返事は、見本として扱われます（解析失敗）。
- 項目が2種類以下の短い返事は、ブロックとして扱いません。
- 値の途中にタグの文字列があると、ブロックの切り方が乱れます。入れ子・交差したタグも同様です。
- 1行に詰められた返事の中の重複項目は、検出しません。
- 同じ返事を引用と本物で二重に含むと、どちらか決められず解析失敗になります（再送が必要）。

## 分かっている不具合・改善待ち

- **問いの中のファイル名を、資料（SOURCE）と取り違えます。** 例：問いに「from-Codex.md」と書くと、資料 S1 として扱われ、AI がそのファイルを探しに行きます。問いにはファイル名を書かないでください（改善予定）。
- **差分欄に、相違点の一部しか出ないことがあります。** 統合の返事の改行が失われていると、相違点が1件にまとまって表示されます。統合の原文には全部残っています（改善予定）。
- 設定画面で、Meta の中継先の表示が保存値と一致しません（動作には影響しません）。
- 実行タスクの「やってほしいこと」（NEXT_TASK）は、統合結果の文がそのまま入り、画面では直せません。範囲を限定したいときは、判断の理由に書いてください（理由は実行タスクに載ります）。
- 形式外の返事を、判断（GATE）の前に必ず確認させる仕組み（段階2）は、まだありません。

## 独立性について

- 観測依頼には、ほかの AI の結果を入れていません。ただし、同じ AI を観測・統合・実行に重ねて指名することは止めていません。止めるかどうかは人間が決めることです。
- 統合 AI が観測者と同じだと、自分の観測に寄りやすくなります。画面上で警告はしません（今後の課題）。
