# AI Team Studio — 実運用版 001

問いを1つ書くと、Studio が SOURCE の整理、各AIへの依頼文づくり、結果の記録、差分の整理、統合依頼、人間の判断（GATE）、次の実行タスクまでを順に進めます。人間が行うのは、問いを書くこと・判断すること、そして AI とのあいだで依頼と返事を運ぶことです。手動のAIでは、依頼文をコピーして AI に貼り、返事を Studio に貼り戻します。ローカル中継のファイル受け渡しでは、AI に「依頼ファイルを読んで結果ファイルを書く」よう伝えます。

7段階（CASE → SOURCE → OBSERVE → DIFFERENCE → SYNTHESIS → HUMAN GATE → NEXT）はそのまま残しています。ただし人間が段階ごとに入力する必要はありません。画面上部の「次にすること」に、その時点で押すボタンが1つか2つ出るだけです。

## 開き方

ビルドは不要です。Web Crypto（ハッシュ計算）を使うため、`file://` ではなく localhost で開いてください。

```text
cd operational-studio-001
python -m http.server 8773 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8773/` を開きます。

## AIとのつなぎ方（コネクタ）

AIごとに、右上の「AIの接続設定」で選びます。

| コネクタ | 動き | 人間の手間 |
|---|---|---|
| 手動（既定） | 依頼文をクリップボードにコピーする。人間がそのAIに貼り、回答を Studio に貼り戻す | コピー1・貼り付け2 |
| ローカル中継 / agent | 中継が `proxy/exchange/<CASE>/<TASK>/to-<AI>.md` を書く。Claude Code や Codex がそれを読み、同じフォルダに `from-<AI>.md` を書く。Studio は8秒ごとに自動で回収する | 依頼ごとに、AI に「この to- ファイルを読み、同じフォルダに from- ファイルを書いて」と伝える。中継は AI を起動しない。伝える文面とファイルの場所は、まだ画面に出ない |
| ローカル中継 / api:openai・anthropic・gemini | 中継がサーバー側でAPIを呼び、回答を返す | なし（**未検証**。送付に失敗した依頼を送り直すと重複処理になる可能性がある。LIMITATIONS 参照） |
| ローカル中継 / mock | 内容のない模擬応答を返す。運搬経路のテスト専用 | なし |

AI への依頼文は、手動ならクリップボードへ、中継なら 127.0.0.1 の中継へだけ渡します。外部の API へ送るのは中継です。ただし、問いに URL があると、ブラウザがその URL を直接取得してハッシュを計算します（資料の確認のため）。

### ローカル中継の起動

```text
cd operational-studio-001/proxy
python studio_proxy.py            # http://127.0.0.1:8787
```

必要なのは Python 3 の標準ライブラリだけです。起動したら、Studio の「AIの接続設定」で中継URLに `http://127.0.0.1:8787` を入れ、「接続を確認」を押します。

## APIキーの扱い（重要）

- APIキーは **HTML・JS・GitHub には一切書きません**。ブラウザ側にはキーを入れる欄がありません。
- キーは `proxy/.env`（`.gitignore` 済み）または環境変数に置きます。書式は `proxy/.env.example` にあります。
- 中継は `127.0.0.1` のみで待ち受けます。CORS で許可しているのは localhost と `https://akirameikyou.github.io` だけです。
- `proxy/exchange/`（AIとのやりとりの実ファイル）も `.gitignore` 済みです。

## 記録

- 保存先はこのブラウザ（localStorage）です。保存データが読めないときは保存を止め、上書きを防ぎます。画面上部に警告が出ます。
- 「記録をJSONで保存」で書き出し、「JSONを読み込む」で復元できます。読めない保存データからの復旧にも使えます。
- 「Markdownで保存」で、問い・SOURCE・各観測・差分・統合・判断・次タスク・受信の記録・依頼文の本文を1つの文書にまとめます。
- 受信した返事は、解析に失敗したものも含めてすべて記録します（原文・経路・時刻・解析結果）。採用中の結果と「利用可能か」は別に表示します。
- AI の返事に「確認済み」「APPROVE」と書いてあっても、確認や判断にはなりません。確認と判断は画面の操作だけで記録されます。

## 返事の読み取り（解析ルール v2）

- `[STUDIO_RESULT]`・`[STUDIO_SYNTHESIS]`・`[STUDIO_DONE]` のブロックを読みます（`parse_v2.js`）。前置きの文章、全角の［］：、1行に詰められた返事も読めます。
- 見本の文言のまま・閉じタグなし・値の違う重複・知らない項目名がある返事は「確認が必要」になり、画面で確認するまで統合・判断に使いません。
- 問いから自動で資料（SOURCE）にするのは、URL と絶対パス（C:\…）だけです。ファイル名だけの記述は資料にしません。ファイル名を資料にしたいときは「資料を追加」欄に書いてください。
- 差分欄の相違点は、統合の返事の改行で分けます。改行が失われた返事では「| ORIGIN: 層」の印で分け、「自動分割（改行なし）」と表示します。確実に分けられないときは原文のまま1項目で出します（表示だけで、記録は変えません）。
- 1つの返事に複数種のブロックがあるときは、統合 → 完了報告 → 観測 の順で1つだけ採用し、残りは記録に残します。
- 宛先は返事の TASK で決めます。TASK が無い観測の返事は、その観測の依頼が1回目（世代1）のときだけ、FROM で決めます。古い依頼への返事は「遅着」として記録し、採用しません。宛先が分からない返事は「未割り当ての受信」に並び、人が宛先を選べます。

## 依頼文の保存と送り直し

- 観測・統合・実行タスクの依頼文は、送る前に Case の中へ保存します（Task ID・世代つき）。本文の SHA-256 は、計算できる環境（localhost など）では一緒に記録します。計算できないときは記録せずに保存し、送付は止めません。
- 「依頼文を表示」で、保存した本文をいつでも表示・コピーし直せます。コピーし直しても新しい依頼にはなりません。
- 「作り直して再送（新しい世代）」は別の操作です。Task ID の世代が上がり、前の世代への返事は遅着になります。
- 送付に失敗したとき（中継が止まっているなど）は「送付に失敗」と記録し、「同じ依頼を送り直す」を出します（同じ Task ID・同じ本文）。
- 依頼文をこのブラウザに保存できないときは、送付しません。
- 送付中のボタンは「送付中…」になり、同じタブの中では二重に送られません。同じ Studio を2つのタブで開いた場合は防げません（1つのタブで使ってください。LIMITATIONS 参照）。
- 観測が変わると、それより後の統合・判断・実行タスクは「古い」と表示され、使えなくなります（記録は消えません）。
