# AI Team Studio — 実運用版 001

問いを1つ書くと、Studio が SOURCE の整理、各AIへの依頼文づくり、結果の記録、差分の整理、統合依頼、人間の判断（GATE）、次の実行タスクまでを順に進めます。人間が行うのは、問いを書くこと・判断すること、そして AI とのあいだで依頼と返事を運ぶことです。手動のAIでは、依頼文をコピーして AI に貼り、返事を Studio に貼り戻します。ローカル中継のファイル受け渡しでは、AI に「依頼ファイルを読んで結果ファイルを書く」よう伝えます。

7段階（CASE → SOURCE → OBSERVE → DIFFERENCE → SYNTHESIS → HUMAN GATE → NEXT）はそのまま残しています。ただし人間が段階ごとに入力する必要はありません。画面上部の「次にすること」に、その時点で押すボタンが1つか2つ出るだけです。

## 開き方

ビルドは不要です。Web Crypto（ハッシュ計算）を使うため、`file://` ではなく localhost で開いてください。

```text
cd operational-studio-001
python -m http.server 8773 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8773/` を開きます。

## AIとのつなぎ方（コネクタ）

AIごとに、右上の「AIの接続設定」で選びます。

| コネクタ | 動き | 人間の手間 |
|---|---|---|
| 手動（既定） | 依頼文をクリップボードにコピーする。人間がそのAIに貼り、回答を Studio に貼り戻す | コピー1・貼り付け2 |
| ローカル中継 / agent | 中継が `proxy/exchange/<CASE>/<TASK>/to-<AI>.md` を書く。Claude Code や Codex がそれを読み、同じフォルダに `from-<AI>.md` を書く。Studio は8秒ごとに自動で回収する | 依頼ごとに、AI に「この to- ファイルを読み、同じフォルダに from- ファイルを書いて」と伝える。中継は AI を起動しない。返事を待っている間は「AIへの指示を表示」で、伝える文面と、依頼ファイル・結果ファイルの完全なパスをコピーできる（パスは、中継が実際に書いたファイルの場所。中継がそれを返さない古い版では、推定であることを表示する） |
| ローカル中継 / api:openai・anthropic・gemini | 中継がサーバー側でAPIを呼び、回答を返す | なし（**未検証**。送付に失敗した依頼を送り直すと重複処理になる可能性がある。LIMITATIONS 参照） |
| ローカル中継 / mock | 内容のない模擬応答を返す。運搬経路のテスト専用 | なし |

AI への依頼文は、手動ならクリップボードへ、中継なら 127.0.0.1 の中継へだけ渡します。外部の API へ送るのは中継です。ただし、問いに URL があると、ブラウザがその URL を直接取得してハッシュを計算します（資料の確認のため）。

### ローカル中継の起動

```text
cd operational-studio-001/proxy
python studio_proxy.py            # http://127.0.0.1:8787
```

必要なのは Python 3 の標準ライブラリだけです。起動したら、Studio の「AIの接続設定」で中継URLに `http://127.0.0.1:8787` を入れ、「接続を確認」を押します。確認できるのは中継に届くかどうかだけで、AI との往復は確かめません。受け渡しフォルダの場所はこのとき記録されます（中継がファイルの場所を返さない古い版で、パスを推定するときだけ使います。中継の URL を変えたり、確認に失敗したりすると消えます）。

## APIキーの扱い（重要）

- APIキーは **HTML・JS・GitHub には一切書きません**。ブラウザ側にはキーを入れる欄がありません。
- キーは `proxy/.env`（`.gitignore` 済み）または環境変数に置きます。書式は `proxy/.env.example` にあります。
- 中継は `127.0.0.1` のみで待ち受けます。CORS で許可しているのは localhost と `https://akirameikyou.github.io` だけです。
- `proxy/exchange/`（AIとのやりとりの実ファイル）も `.gitignore` 済みです。

## 記録

- 保存先はこのブラウザ（localStorage）です。保存データが読めないときは保存を止め、上書きを防ぎます。画面上部に警告が出ます。
- 「記録をJSONで保存」で書き出し、「JSONを読み込む」で復元できます。読めない保存データからの復旧にも使えます。
- 「Markdownで保存」で、問い・SOURCE・各観測・差分・統合・判断・次タスク・受信の記録・依頼文の本文を1つの文書にまとめます。
- 受信した返事は、解析に失敗したものも含めてすべて記録します（原文・経路・時刻・解析結果）。採用中の結果と「利用可能か」は別に表示します。
- AI の返事に「確認済み」「APPROVE」と書いてあっても、確認や判断にはなりません。確認と判断は画面の操作だけで記録されます。

## 起動と停止（いちばん簡単な方法）

- **起動**：`start_studio.bat` をダブルクリックします。中継（8787）とスタジオ（8773）を、動いていなければ起動し、Chrome で `http://localhost:8773/` を開きます（Chrome が無ければ既定のブラウザ）。中継の状態（使える API）も表示します。どの AI にも何も送りません。
- **停止**：`stop_studio.bat`。このスタジオの中継とページの Python だけを止めます。記録はブラウザに、記録の写しは `proxy/exchange/_snapshots` に残ります。
- **Chrome で開く理由**：Chrome は、このページの記録（localStorage）とサインイン（ChatGPT など）を次回も残します。アドレスは必ず `localhost` を使ってください（`127.0.0.1` で開くと、ブラウザは別の場所に記録を保存します）。
- **初期設定**：ブラウザに記録がないとき（初めて開いたとき・記録が消えたとき）、スタジオは中継から初期設定（`proxy/studio.config.json`：中継の URL と各 AI の渡し方。秘密は含みません）を読み込み、記録の写しがあれば戻すかどうかを聞きます。記録があるブラウザでは、起動時に設定を変えません。「AIの接続設定」の「初期設定に戻す」で、いつでも読み込み直せます（記録の Case は変わりません）。
- 必要なもの：Python 3（標準ライブラリだけ）。Gemini の API を使う場合は `proxy/.env` にキー（利用者が自分で書く）。

## 前提資料・記録の写し・中継の決まり（段階2）

- **前提資料（本文）**：Case を作る画面の「前提資料を付ける」、または資料欄の「本文として追加」で、本文そのものを資料にできます。全文が、観測・統合・実行タスクのすべての依頼文に「■ 資料本文」として入り、SHA-256 と大きさが記録されます。1件の上限は 200,000 文字です（JavaScript の文字数で数えるため、絵文字など一部の文字は2文字と数えます。ブラウザの保存領域を守るための安全側の数え方です）。中継につないだ AI には「始める」と同時に依頼が送られるので、前提資料は Case を作る前に入れてください。
- **Case 番号**：`CASE-年月日-連番-乱数6文字` です。ブラウザの記録が消えて連番が 001 に戻っても、乱数の部分（約22億通り）で、以前の Case と同じ番号になる可能性をごく小さくします（重ならないことの保証ではありません）。中継を使っているときは、中継のフォルダに同じ番号がないことも確かめます（確かめるだけで、予約はしません）。
- **記録の写し**：中継を使っているとき、記録を保存するたびに、間を置いて（3秒）その時点の記録の写しを中継へ送ります。写しは `proxy/exchange/_snapshots/` に1回ごとに別のファイルとして残り、上書きも削除もされません。送れなかったときは、左下の「記録の写し」に失敗と表示されます。
  - 戻し方：左の「記録の写しから戻す」で写しを選びます。今の記録は、Case が0件でも（接続の設定などを含むため）、置き換える前に写しとして保存されます。その写しを保存できなかったときは、置き換えるかどうかを確認します。戻した記録を保存できなかったときは、今の記録のまま変えません。
  - 写しは平文の JSON です（`proxy/exchange/` は Git の管理外）。**どれだけ残すか・いつ消すかは人間が決めます**（中継もスタジオも自動では消しません。件数にも合計の大きさにも上限はありません）。左下の「記録の写し」に、件数と合計の大きさが出ます。外に出せない内容を含む場合は、置き場所の扱いに注意してください。
  - 写しのファイル名の `r番号` は、保存の回数です。写しから戻すと、その写しの番号から数え直すので、番号は巻き戻ることがあります。写しの新しさは、ファイル名の日時で判断してください（一覧もその順です）。
  - 写しの読み書きを受け付けるのは、このパソコンの中のページ（localhost / 127.0.0.1。ポートは問わない）と、Origin を送らないこのパソコンの中のプログラムです。GitHub Pages など外のページからは受け付けません。**これは送り元の確認で、認証ではありません**（このパソコンで動く別のページやプログラムは読み書きできます）。写しの名前は決まった形のものだけを読み、別の場所を指すファイル（シンボリックリンク）は読みません。写しのフォルダそのものがリンクなら、写しを読み書きしません。ただし、確かめてから読むまでの間に、このパソコンの中のプログラムがファイルを差し替える場合までは防げません。
  - 写しは、**保存できた内容**から作ります。保存に失敗した後は、画面に出ている内容のうち保存できなかった分は写しに入りません（戻す前に知らせます）。そのときは「記録をJSONで保存」で書き出してください。
  - 写しの送信は、20秒で応答がなければ失敗として扱います。送信中の写しの後ろに待つのは1件までです（待っている写しは、送り始めるときの保存済みの内容を読むので、何件積んでも同じ内容になるため）。
  - **スタジオは1つのタブで使ってください。** 2つのタブで同時に Case を作ると、まれに同じ番号を選ぶ可能性があります（中継の確認は予約ではないため）。
- **返事ファイルの書き手は1人**：ファイル受け渡し（agent）の返事 `from-<AI>.md` を書くのは、その AI だけです。API の経路では中継だけが書きます。1つの返事ファイルを2つの書き手が書く使い方はしません（中継の順番待ちは、中継の中だけで効くため）。返事を書く AI には、一時ファイルに書き終えてから名前を変えるよう依頼文で頼んでいます。中継は、最後に変更されてから2秒以内の返事ファイルを、書きかけかもしれないとして読みません。
- **中継が書くファイル**：依頼ファイルと API の返事は、スタジオが記録したバイト列のまま書きます（改行を変えません）。書き終えてから名前を差し替えるので、書きかけのファイルは外から見えません。

## 返事の読み取り（解析ルール v2）

- `[STUDIO_RESULT]`・`[STUDIO_SYNTHESIS]`・`[STUDIO_DONE]` のブロックを読みます（`parse_v2.js`）。前置きの文章、全角の［］：、1行に詰められた返事も読めます。
- 見本の文言のまま・閉じタグなし・値の違う重複・知らない項目名がある返事は「確認が必要」になり、画面で確認するまで統合・判断に使いません。
- 問いから自動で資料（SOURCE）にするのは、URL と絶対パス（C:\…）だけです。ファイル名だけの記述は資料にしません。ファイル名を資料にしたいときは「資料を追加」欄に書いてください。
- 差分欄の相違点は、統合の返事の改行で分けます。改行が失われた返事では「| ORIGIN: 層」の印で分け、「自動分割（改行なし）」と表示します。確実に分けられないときは原文のまま1項目で出します（表示だけで、記録は変えません）。
- 1つの返事に複数種のブロックがあるときは、統合 → 完了報告 → 観測 の順で1つだけ採用し、残りは記録に残します。
- 宛先は返事の TASK で決めます。TASK が無い観測の返事は、その観測の依頼が1回目（世代1）のときだけ、FROM で決めます。古い依頼への返事は「遅着」として記録し、採用しません。宛先が分からない返事は「未割り当ての受信」に並び、人が宛先を選べます。

## 依頼文の保存と送り直し

- 観測・統合・実行タスクの依頼文は、送る前に Case の中へ保存します（Task ID・世代つき）。本文の SHA-256 は、計算できる環境（localhost など）では一緒に記録します。計算できないときは記録せずに保存し、送付は止めません。
- 「依頼文を表示」で、保存した本文をいつでも表示・コピーし直せます。コピーし直しても新しい依頼にはなりません。
- 「作り直して再送（新しい世代）」は別の操作です。Task ID の世代が上がり、前の世代への返事は遅着になります。
- 送付に失敗したとき（中継が止まっているなど）は「送付に失敗」と記録し、「同じ依頼を送り直す」を出します（同じ Task ID・同じ本文）。
- 依頼文をこのブラウザに保存できないときは、送付しません。
- 送付中のボタンは「送付中…」になり、同じタブの中では二重に送られません。同じ Studio を2つのタブで開いた場合は防げません（1つのタブで使ってください。LIMITATIONS 参照）。
- 観測が変わると、それより後の統合・判断・実行タスクは「古い」と表示され、使えなくなります（記録は消えません）。
